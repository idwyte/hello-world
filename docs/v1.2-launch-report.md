## Pivot summary

The original v1.1 onboarding tested pelvic-floor function via 3 screen-tap measurements (reaction time, endurance press-and-hold, rapid taps). Users would see through the lack of mechanistic link to the muscle group being trained. v1.2 replaces those inputs with **two real measurements** and **four lifestyle questions**, then generates a personalised 8-week program via **Claude Haiku 4.5** behind a Supabase Edge Function.

- ✅ 9 new Figma screens drafted via MCP and approved
- ✅ New scoring formula (40 % pulse / 60 % hold weighting per Bø & Sherburn 2005)
- ✅ Edge Function `generate-program` calling Claude with prompt-cache directive
- ✅ Rule-based fallback for the no-backend / Edge-Function-error path so onboarding never blocks on the LLM
- ✅ Exercise catalog expanded from 5 → 12 (holistic palette: pure floor + release + hybrid + synergists + mobility)
- ✅ Bi-weekly retest cadence with soft 14-day enforcement
- ✅ Shared pulse/hold UI used by both onboarding and the retest flow

## What you need to deploy

### 1. Anthropic account
Sign up at `console.anthropic.com` (free), fund a balance ($5 min) or attach a card, generate an API key (`sk-ant-api03-...`).

### 2. Supabase secret
```sh
supabase secrets set ANTHROPIC_API_KEY=sk-ant-api03-...
```

### 3. Edge Function deploy
```sh
supabase functions deploy generate-program
```

### 4. SQL migration
```sh
supabase db push  # applies supabase/migrations/0005_assessment_pivot.sql
```
**Heads-up:** the migration `TRUNCATE`s the existing `pelvic_floor_assessments` table because the new measurement columns (`pulses_in_30s`, `max_hold_s`) replace the old (`reaction_ms`, `endurance_s`, `rapid_reps_10s`) and there's no meaningful conversion. Existing user trends are lost; they get a fresh baseline on next retest. Safe at this stage — no users in production yet. Will need an additive migration if v1.2 ships to anyone before this lands.

Until #2-#4 are done, the app stays on the rule-based fallback path. The user flow works end-to-end; the plan is just generic-per-level rather than AI-personalised.

Each stub has a `// Figma: NN · screen-name — node N:M` header comment and a `// FIGMA-DIFF:` list of what's deferred. Priorities:

4. **`restore.tsx` (20)** + **`delete-account.tsx` (29)** — App Store compliance.

### Legacy reskin pass

`welcome.tsx`, `paywall.tsx`, `plan-preview.tsx`, and `session/{player,today,stealth}.tsx` work but don't match the design system tokens / Figma nodes. Especially `plan-preview` since it's the first thing the user sees after onboarding — currently shows static day cards without the composite hero / focuses / week 1 preview from Figma 11.

### Edge Function unit test (Phase G deferred)

The Edge Function is Deno-runtime code and not naturally Jest-runnable. Either run via Deno's own test runner (`supabase functions test` exists) or extract the prompt + schema to a shared module that imports cleanly in both. The function's behaviour is already exercised via the `buildProgram` async-path mocks added in Phase C.

### Paywall pricing decision

Figma says $8.99 one-time (`hone_lifetime`); code currently bills $5.99/wk + $24.99/yr. PM call, not a code one.

### Domain expert review of the exercise catalog

The 7 new entries in `lib/exercises.ts` (reverse_kegels, pulse_hold_combo, adductor_squeeze, glute_bridge, bird_dog, deep_squat_breath, tabletop_marches) were authored from general knowledge with PT-flavored descriptions. Worth a pelvic-floor PT's eyes before shipping — phase timings, set/rep defaults, and especially the bear-down framing on `reverse_kegels` (where my phase-kind labels approximate the timing pattern because the session engine has no native "release-downward" phase).

## Things I would NOT do before shipping v1.2

- **Don't add Phase 2/3 features**. Streak-freeze (37), anonymous sign-up (38), Live Activity widget (41) — all designed in Figma, all deferred per the original roadmap. Ship the assessment pivot first.
- **Don't optimise the Claude prompt for caching yet**. The system prompt is ~1.1K tokens (Haiku cache minimum 4096). Caching activates once we add detailed exercise rationale or example weeks — that's a Phase 2 polish task with telemetry, not a launch blocker.
- **Don't promote the Edge Function unit test to a launch blocker**. End-to-end coverage exists via the async-path mocks; the function's logic is small and inspectable.
